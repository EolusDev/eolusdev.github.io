官方升级后怎么办

新版出来，无需逆向重做

工具链与版本号无关。官方 Sparrow 升级后，按以下四步即可重新生成新版中文版。

安装新版原版 Sparrow

安装官方新版，取得其 runtime\lib\modules 镜像文件。

用现有字典重建

对新的镜像运行 build.py，绝大部分界面文字沿用现有 2359 条字典（分批字典自动合并）。

$ python 中文补丁/patch/脚本/build.py --src "D:\Sparrow" --install

扫描未覆盖的英文字面量

运行 scan_remaining.py，找出新版里尚未翻译的可见英文文案。

$ python 中文补丁/patch/脚本/scan_remaining.py

补字典并重跑，校验通过即完成

把新增文案补进对应分批字典，重跑 build.py，自动完成解包、翻译、重建与哈希校验。

注意：与外部值比较的字符串（协议判断、过滤排序、SQL、日志）不可翻译，判别口径见仓库 安装说明.md。

技术原理 · 就地改写 jimage

不改字节码，只改界面文字

Sparrow 由 jpackage 打包，字节码与资源都在 runtime\lib\modules 镜像里。构建管线分四步，全程纯 Python 标准库。

STEP 01

解包镜像

按 jimage 格式（小端、完美哈希、zlib 压缩块）纯 Python 解出 sparrow 模块。

STEP 02

FXML 界面翻译

替换 text / promptText / helpText 属性与可见文本节点，注释块移到文件尾。

STEP 03

Java 常量池改写

只替换未被类名 / 字段 / 方法引用的 Utf8 字面量，重建常量池，绝不动标识符与字节码逻辑。

STEP 04

就地重建 + 校验

保持哈希表与字符串表字节不变，全量检查完美哈希失配数（须为 0）并统计中文资源。

同一原始镜像 + 同一字典 → 构建产物字节一致（SHA256 交叉验证） 曾尝试 jlink 整体重链接，因 JDK 小版本不兼容弃用，改用就地改写方案并通过实际启动验证
